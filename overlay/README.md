# らみん民 LIVE Overlay

既存のガチャ・ルーレットから独立した、Firebase読み取り専用オーバーレイ。

## 開き方
- `overlay/display.html?demo=1`：Firebase非接続のデモ
- `overlay/display.html?env=prod`：本番の新着ギフト
- `overlay/display.html?env=test`：既存のテスト環境の新着ギフト

PRISM LIVEのWebソースは1080×1920を推奨。背景は透明。

## 実装済み
- 新着キューのギフト通知
- `repeatCount` を考慮したギフト個数・送信者ランキング
- `localStorage` によるブラウザ内の集計・カーソル保存
- デモ表示、いいねペット・出席スタンプのプレースホルダー

## 制約と注意
- **Firebaseへの書き込み・Workerの変更は行わない。** 既存ガチャの再生担当・カーソルに干渉しない。
- 初回起動時は過去のキューを飛ばす。以降は保存したカーソルより新しいイベントを処理する。
- 保存はブラウザ内のみ。PRISMとSafariは別の保存領域になる可能性がある。アプリのデータ削除やプライベートモードでは失われる。
- Firebaseのキュー保持件数は300件。長時間停止中にそれ以上のイベントが来ると、再開時に取りこぼす可能性がある。
- キューに登録されるのは抽選対象となったギフトだけ。**全ギフト・ダイヤ額・LIVE全体ランキングを表すものではない。**
- `sender` は表示名のため、同名ユーザーを区別できない。
- いいね・フォロー・コメント・出席イベントの実受信は未実装。
- 既存のガチャ・ルーレットを一つのWebソースに統合する処理は未実装。
- PRISM実機テスト、Firebase実データでの検証は未実施。

## 日別集計
- 日本時間（Asia/Tokyo）の日付を基準に、ページ起動時・新着イベント受信時に加え、表示中も30秒ごとに日付変更を確認して切り替える。
- 過去のキューを再集計しないため、受信日時（`receivedAt`）のあるイベントは、再開時に当日以外の分を当日集計へ加えない。受信日時が欠落したイベントは処理時の日付で扱う。
- 全配信・全ギフトを対象とした全ギフトを対象とした正確な日次集計にはWorker側での集計が必要。

## 統合表示
- `overlay/combined.html?env=prod` : 既存ガチャ・ルーレットとオーバーレイを1つのブラウザソースに重ねる（実機未検証）。
- ガチャ画面に必要な既存の表示用URLパラメータも指定する。キーの共有・公開に注意。
- 統合ページの技術的な注意点は `README-add.md` を参照。

## PRISM表示の調整
- `layout=compact` : 初期値。ランキングを上部へ寄せ、出席パネルは隠す
- `layout=full` : すべてのパネルを表示
- `layout=minimal` : ギフト数と通知を中心に小さく表示
- `hide=ranking,pet` : 指定したパネルを隠す。指定可能: `counter,pet,ranking,attendance,brand,mode`
- 例: `overlay/combined.html?env=prod&layout=minimal&hide=mode`

`layout` と `hide` は統合ページからも引き継がれます。

## デモのイベント演出
- `?demo=1` で、ギフトに加え、いいねペット・出席スタンプ・フォロー・コメント通知を順に再生する。
- デモイベントはFirebaseやWorkerへ送信しない。カウンターのデモ状態は保存しない。
- 実際のいいね・出席イベントの受信はまだ未接続。

## デモ時の通信
- `?demo=1` のときはFirebase SDKを読み込まない。接続情報が設定されていなくてもUIのデモを確認できる。
