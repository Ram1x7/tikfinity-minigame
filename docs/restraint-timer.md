# 縛りタイマー：配信導入と素材仕様

## 実装した素材
- `assets/timer/frame-active.svg` — 実行中：紺×金
- `assets/timer/frame-waiting.svg` — 待機中：紺×銀
- `assets/timer/frame-parallel.svg` — 並行中：紫×金

SVGは背景透過の装飾素材。文字・残り時間・進捗は描画時にHTMLで重ねるため、画像内に固定の数字や文字はありません。既存のガチャ・ルーレット台紙には触れません。

## レイアウト
- 1080×1920を基準に、左54px・上1190px、幅650px
- 1枚132px、高さ方向の間隔9px
- 4件まで表示し、5件目以降は件数でまとめる
- 縛り名・実行状態・残り時間・進捗バーをリアルタイム表示
- 背景は透過、ブラウザソースは既存の `display.html` を共用する

## 縛り設定
1. 管理画面の抽選テーブルで候補の「縛りタイマーを使用」をONにする
2. IDは英数字と `_` `-` のみ。**同じ縛りには同じID** を使う
3. 制限時間を分単位で設定
4. 釣り・虫捕り・料理は「専用行動」、ジャンプ禁止などは「並行可能」
5. 設定保存後、管理画面の「全再開」を押してタイマーを開始可能にする

## ルール
- 専用行動は同時に1件。次の縛りは待機中に時間を減らさない
- 同じIDの再当選は、実行中・待機中どちらも残り時間に加算
- 専用行動の終了時に次の待機中の縛りが自動開始。移動時間も含む
- 並行可能な縛りは専用行動と同時にカウント
- 配信終了時は「全停止」、次回配信開始時に「全再開」
- Firebaseのタイマー状態は配信画面を再読み込みしても維持

## デプロイ前の必須チェック
1. `npm install`（必要なら）、`npm run build`、`npm test`、`npm run check` を実行
2. **テスト環境のみ**でWorkerコードをCloudflareに貼り付け、Firebaseの読取・書込・認証を確認
3. 管理画面でタイマー設定を保存し、テストギフトを送信
4. PRISM/iPadの表示、順番待ち、重複当選、加算、停止・再開、配信終了後の復元を検証
5. テスト合格後に本番ブランチへマージし、Workerを本番デプロイ
6. 本番管理画面でタイマー設定をONにし、配信前に「全再開」

**注意**：GitHub Pagesの公開とCloudflare Workerのデプロイは別操作です。GitHubへのコード追加だけではWorkerは更新されません。タイマー機能の本番投入にはWorkerの更新が必要です。配信終了の自動検知は未実装です。
