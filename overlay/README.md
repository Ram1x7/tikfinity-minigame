# らみん民 LIVE Overlay

既存のガチャ・ルーレットから独立した、Firebase読み取り専用オーバーレイ。

## 開き方
- `overlay/display.html?demo=1`：Firebase非接続のデモ
- `overlay/display.html?env=prod`：本番の新着ギフト
- `overlay/display.html?env=test`：既存のテスト環境の新着ギフト

PRISM LIVEのWebソースは1080×1920を推奨。背景は透明。

## 実装済み
- 新着キューのギフト通知
- `repeatCount` を考慮したギフト個数・送信者ランキング
- `localStorage` によるブラウザ内の集計・カーソル保存
- デモ表示、いいねペット・出席スタンプのプレースホルダー

## 制約と注意
- **Firebaseへの書き込み・Workerの変更は行わない。** 既存ガチャの再生担当・カーソルに干渉しない。
- 初回起動時は過去のキューを飛ばす。以降は保存したカーソルより新しいイベントを処理する。
- 保存はブラウザ内のみ。PRISMとSafariは別の保存領域になる可能性がある。アプリのデータ削除やプライベートモードでは失われる。
- Firebaseのキュー保持件数は300件。長時間停止中にそれ以上のイベントが来ると、再開時に取りこぼす可能性がある。
- キューに登録されるのは抽選対象となったギフトだけ。**全ギフト・ダイヤ額・LIVE全体ランキングを表すものではない。**
- `sender` は表示名のため、同名ユーザーを区別できない。
- いいね・フォロー・コメント・出席イベントの実受信は未実装。
- 既存のガチャ・ルーレットを一つのWebソースに統合する処理は未実装。
- PRISM実機テスト、Firebase実データでの検証は未実施。

## 日別集計
- 日本時間（Asia/Tokyo）の日付を基準に、次のギフト受信時またはページ起動時に日別集計を切り替える。日付変更だけでは表示は更新されない。
- 過去のキューを再集計しないため、停止中に日付をまたいで受信したイベントは、再開した日の集計に含まれる場合がある。
- 全配信・全ギフトを対象とした正確な日次集計にはWorker側での集計が必要。
