# ギフトガチャ｜やることリスト

既存のギフトガチャにのみ適用。ルーレット・縛りタイマーには影響しない。

- Webhookまたは疑似ギフトでガチャ抽選が成立すると、**各抽選結果を1件ずつ** `envs/{env}/state/gachaTodo/pending` に追加する。
- 同じ内容でも統合しない。Firebaseの抽選キューのpush IDと抽選順indexを使って順番を維持。
- PRISMの既存 `display.html` に**先頭5件**だけ表示し、総件数も表示。
- 既存 `admin.html` の「ギフトガチャ｜やることリスト」で「完了」を押すと該当1件を削除。次の1件が自動表示。
- 「未完了を全リセット」は確認ダイアログを経て全削除。
- Firebaseの既存 `state` 読み取り権限を利用するため、`database.rules.json` の変更は不要。
- キューから古い抽選が削除されても、未完了タスクは保持される。管理画面・PRISMの再読み込み後も保持。
- 既存の縛りタイマー用リセットとは別管理。
- 表示位置はゲーム画面左側（1080×1920基準で x=34, y=480）。コメント欄やランキングを避ける初期位置。

## 本番への導入

1. CIが成功していることを確認し、PRを `main` に統合する。
2. GitHub Pagesの公開完了を待つ。
3. Cloudflareの**既存Worker**を、最新 `main/worker/dist/worker.js` で再デプロイする。SecretsやWebhook URLは変更しない。
4. 既存管理画面 `admin.html?env=prod` を更新し、やることリスト欄があるか確認。
5. 既存PRISMの `display.html?env=prod&dk=...` を再読み込みする（URLや合言葉は変更しない）。
6. 管理画面の疑似ギフトでガチャを2回発生させ、同じ内容が2件並ぶことを確認。「完了」で1件だけ消えることを確認。
7. 既存ルーレットと縛りタイマーの動作が変わっていないことを確認。

**注意:** Workerが旧版のままでは、管理画面の「完了」操作は404になります。GitHub PagesとWorkerを両方更新してください。
