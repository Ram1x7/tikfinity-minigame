# 配信運用マニュアル(ガチャ・ルーレット)

TikTok LIVE で和風のガチャ・ルーレットを使うための、URL 一覧・配信の手順・困ったときの直し方・本番反映の手順です。
合言葉(`k=` `dk=` や管理用の合言葉)はこの文書にも GitHub にも書きません。パスワード管理アプリで管理してください。

## 1. 全体のつながり

```
視聴者がギフトを送る
  → TikFinity が Webhook を送る(中継のページはありません。TikFinity から Worker に直接届きます)
  → Cloudflare Worker:合言葉の確認 → 重複の確認 → ギフトの設定と照合 → 抽選(ここで1回だけ確定)
  → Firebase の「再生待ち」に追加
  → 表示画面(PRISM LIVE の Web ソース)が届いた順に1件ずつ再生
```

- 抽選は Worker だけが行います(表示画面は結果を見せるだけ)。重み(当たりやすさ)どおりに選ばれます。
- 連続ギフトは、TikFinity が送る `repeatEnd`(確定)で1回にまとめます。届かない場合は、ギフトの設定を「何個でも1回だけ抽選」にします。
- 同じ環境で再生する表示画面は1つだけです(2つ開いても二重に再生しません)。

## 2. URL 一覧

本番のサイトは GitHub Pages(`main` ブランチ)です。`<…>` の部分はご自分の値に置き換えます。

| 用途 | URL | 開く場所 |
|---|---|---|
| 表示画面(配信用) | 管理画面の「URL の案内」→ 本番の表示画面の URL をコピー(`display.html?env=prod&dk=…&theme=wafu…`) | PRISM LIVE の Web ソース(1080×1920) |
| 管理画面(本番) | `https://ram1x7.github.io/tikfinity-minigame/admin.html?env=prod` | iPhone / iPad の Safari |
| 管理画面(テスト) | `https://ram1x7.github.io/tikfinity-minigame/admin.html?env=test` | 同上 |
| テスト画面 | `https://ram1x7.github.io/tikfinity-minigame/test.html?env=test` | 同上 |
| 見本(大きさ合わせ) | `https://ram1x7.github.io/tikfinity-minigame/display.html?demo=1&theme=wafu` | PRISM LIVE(合言葉なし) |
| TikFinity の Webhook | `https://<本番 Worker>.workers.dev/webhook?env=prod&k=<WEBHOOK_KEY>` | TikFinity のアクション |

確認用のプレビュー(テスト専用の Firebase・Worker につながり、本番のデータには触れません):

| ブランチ | URL |
|---|---|
| wafu-preview | https://tikfinity-minigame-preview.pages.dev |
| wafu-roulette-work | https://wafu-roulette-work.tikfinity-minigame-preview.pages.dev |

- 表示画面の URL には `dk=`(表示用の合言葉)が入ります。**配信画面・スクリーンショット・人に見せない**でください。
- 表示の位置・大きさ・コメント欄よけを変えたら、PRISM の URL も貼り直します(設定は URL に入ります)。

## 3. 配信前のチェック(毎回・5分)

1. 管理画面(本番)を開き、上部に「本番」と出ていることを確認する。
2. 「接続設定」→「接続テスト」がすべて ✓(Worker のバージョン 1.4.0、シークレット設定済み)。
3. 「表示画面の再生担当」が「担当あり」(PRISM の表示画面が担当になっている)。
4. テスト画面で、**テスト環境**に疑似ギフトを1件送り、テスト用の表示画面で再生されることを確認する(本番の再生待ちを汚さないため)。
5. 本番で確かめるときは、配信前に自分で小さなギフトを1つ送り、PRISM で再生 → 透明に戻ることを確認する。

## 4. 配信の開始

1. PRISM LIVE を起動し、Web ソース(本番の表示画面の URL、1080×1920)がゲーム画面より上にあることを確認する。
2. TikFinity を起動し、Webhook のアクションが**本番(`env=prod`)**の URL になっていることを確認する。
3. 配信を開始する。
4. 最初のギフトで、管理画面の「受信ログ」に記録が出ることを確認する(出ない場合は「5. 困ったとき」)。

配信の終了後は、PRISM の Web ソースを閉じてかまいません。再生待ちが残っていれば、次に開いたときに続きから再生します
(古すぎるものは「全体設定 → 古い未再生イベントを飛ばす」の分数で自動的に飛ばします)。

## 5. 困ったとき(上から順に確認)

| 症状 | 直し方 |
|---|---|
| ギフトが来ても何も起きない・受信ログに何も出ない | TikFinity の Webhook URL(`env=prod`、`k=` の合言葉、Worker の URL)を確認。TikFinity 側でアクションがギフトのイベントに結び付いているか |
| 受信ログに「未設定のギフト」 | ログの「このギフトを設定に追加」を押し、抽選テーブルを選んで保存 |
| 受信ログには出るが、PRISM に何も出ない | 管理画面の「表示画面の再生担当」を確認。担当なし → PRISM の Web ソースを再読み込み。別の画面が担当 → 「再生担当を外す」(最大30秒で切り替わる) |
| 表示画面に「表示用の合言葉が違います」「dk が URL にありません」 | 管理画面の「URL の案内」から表示画面の URL をコピーし直して、PRISM に貼り直す |
| 連続ギフトで何回も再生される | ギフトの設定の「連続ギフトのとき」を「何個でも1回だけ抽選」にする |
| 再生待ちが溜まりすぎた | 表示画面の URL の末尾に `&skip=1` を付けて開き直す(未再生分を飛ばして最新から) |
| 文字がぼやける・小さい | PRISM の Web ソースを 1080×1920 にする。視聴者側だけ崩れるときは URL に `&soft=2` |
| 文字がコメント欄に重なる | 管理画面の「表示の調整」でコメント欄よけの線を上げ、出てきた URL を PRISM に貼り直す |
| どうしても直らない | PRISM の Web ソースを一度消して、「URL の案内」の URL で作り直す。それでもだめなら、その配信ではミニゲームを止め、受信ログの画面を保存して後で調べる |

## 6. 本番反映の手順(承認を得てから実施)

今の本番(`main`)は Worker 1.1.0・従来デザインです。和風のガチャ・ルーレットと再生担当の仕組み(Worker 1.4.0)を本番に入れるには、
**Worker → ページ → 確認 → PRISM の URL → Firebase のルール** の順番を守ります(README「10. 再生担当への切り替え手順」と同じ)。

### 6-0. 準備(GitHub)
1. `wafu-roulette-work` を `wafu-preview` に取り込む(PR を作ってマージ)。PR #1(`wafu-preview` → `main`)に和風ルーレットが入る。
2. PR #1 の CI が成功していることを確認する(まだマージしない)。

### 6-1. Worker(Cloudflare)
1. 本番 Worker のシークレットに `DISPLAY_KEY_PROD` と `DISPLAY_KEY_TEST` を追加(長めのランダムな英数字。2つは別の値)。
   **本番 Worker には `ALLOWED_ENVS` を入れない**(入れると本番を受け付けなくなる)。
2. `wafu-preview` の `worker/dist/worker.js` を本番 Worker に貼り付けてデプロイ。
3. 管理画面の「接続テスト」で、バージョン 1.4.0・シークレット設定済みを確認。
4. TikFinity の Webhook URL に `env=prod` が付いていることを確認(付いていないと受け付けない)。
   この時点では、今の本番の表示画面もそのまま動く。

### 6-2. ページ(GitHub Pages)
1. 配信していない時間に、PR #1 をマージする(`main` が更新され、数分で本番のサイトに反映)。
2. マージ後は `dk=` の無い表示画面は再生担当になれず再生しないため、続けて 6-3・6-4 を行う。

### 6-3. 確認(テスト環境)
1. 管理画面(テスト)の「接続設定」に表示用の合言葉(本番・テスト)を入れて保存。
2. 「URL の案内」のテストの表示画面を開き、テスト画面から送ったギフトが再生され「再生済み」になることを確認。
3. ガチャ・ルーレットの N・R・SR・SSR、長い景品名、連続ギフトを確認。

### 6-4. PRISM の URL
1. 管理画面「表示の調整」でデザインを「和風」にし、位置・コメント欄よけを決める。
2. 「URL の案内」の本番の表示画面の URL(`dk=` 付き)を PRISM の Web ソースに貼る。
3. 自分で小さなギフトを送り、本番で再生されることを確認。

### 6-5. Firebase のルール
1. Firebase コンソール → Realtime Database → ルールに、`main` の `database.rules.json` を貼り付けて公開。
   (ブラウザから再生位置を書き換えられなくなる。必ず 6-1〜6-4 の後に行う)

### 元に戻す(逆の順番)
1. Firebase のルールを1つ前の版に戻す(`git show c32abe6:database.rules.json`)。
2. GitHub で PR #1 のマージを revert する(本番のサイトが元に戻る)。
3. Worker を `git show c32abe6:worker/dist/worker.js` の版に戻す(必ずページの後)。
